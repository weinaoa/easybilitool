# 1.1.13 导航安全区点击修复

## 实现范围

原生底栏增加高度、底部内边距后，补出的背景区域没有相应的触摸处理，可能点击到后面的列表。本次让触摸拦截跟随实际安全区视图，只消费从该区域开始的触摸序列；正文开始的滑动继续交给原页面。收起后的透明区域不拦截，移除安全区时完成已接管的序列并清理登记。

覆盖原生首页、详情固定输入栏、设置列表、补出的页面及弹层背景，并为已有 Compose 适配器接入相同策略。未覆盖的透明内容区域不添加全窗口遮罩。

## 本地检查

- 独立构建、13 组 JVM 检查通过，包括触摸边界、多指、取消、移出区域及恢复中途的序列所有权。
- Lint：0 错误，34 个已有警告。
- APK 身份、作用域、类边界、许可证、API 102 依赖隔离及签名审计通过；沿用原签名证书。
- 安装包 SHA-256 和结构化结果见 [JSON 记录](nav-safe-touch-v1113.json)。

## 实机结果

环境：Mi 10、Android 17 / API 37、官方客户端 8.95.0 / 8950600、深色皮肤、手势导航。仅启用本模块作用于宿主，使用本轮 1.1.13 APK。

- 导航沉浸开启、原生首页底栏可见时，底部安全区左、中、右三个位置点击均未打开下方内容。
- 底栏收起后，点击同一区域露出的卡片可以进入内容；未留下覆盖整屏的触摸拦截层。
- 导航沉浸开、关均完成首页、动态正文、动态评论、视频评论及回复详情的上滑、下滑、惯性、重进和键盘往返；视频评论切页后恢复。
- 分别检查隐藏后的列表实际范围和背景；有限回复列表的末项仍位于导航手势区域上方。

## popsicle 补测（2026-10-25）

使用同一修复 APK，在 Android 17 / API 37、1200×2608、官方客户端 8.95.0、自定义浅色皮肤和手势导航下补测。每轮仅启用当前模块作用于宿主。

- 原生底栏可见、导航沉浸开启时，安全区 y=2548～2608 的左、中、右三处点击均未打开背后内容，包含原先复现的位置。
- 原生底栏收起后，点击该位置露出的卡片仍能进入内容。
- 原生模式在沉浸开、关两种配置下，均完成首页、动态正文、动态评论、视频评论及回复详情的滑动、惯性、切页、重进和键盘往返；核查隐藏背景、列表实际范围和有限列表末项距离。
